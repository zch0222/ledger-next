# UI 与交互设计规范

版本 0.3 · 2026-10-02 · 待评审（0.3 增加主题色与深浅模式）；需结合 [交互原型](ui/index.html) 和 [操作逻辑图](USER_FLOWS.md) 阅读。

## 1. 设计目标与信息架构

常用记账应在一次连续输入中完成；总览应回答“花了多少、花在哪里、接下来要付什么”；所有汇总需可追溯到明细。金额、币种、时间口径比装饰更重要。

~~~text
认证 / 首次引导
  登录 → 新建或加入账本 → 基准币种 / 时区 → 首个账户 → 可选提醒绑定
主导航
  总览
  账目                 筛选 / 明细 / 记账 / 更正 / 退款
  订阅                 列表 / 日历 / 账单详情 / 已付 / 暂停
  预算与分析           预算 / 趋势 / 分类 / 账户 / 导出
  账户                 余额 / 转账 / 期初 / 归档
  提醒中心             提醒规则 / 接收渠道 / 投递记录
  设置                 账本 / 成员 / 分类 / 汇率 / Agent 接入 / 数据 / 外观
全局操作
  账本切换、展示币种、日期范围、外观（深浅模式 / 主题色）、快捷记账、账户菜单
~~~

P00–P13 是页面验收编号。桌面主导航侧栏；移动底栏为“总览、账目、记一笔、订阅、更多”，更多页进入预算、账户、提醒、设置、外观。修改 URL 后刷新、返回应保留筛选条件。

## 2. 视觉系统

产品暂名 Ledger Next，中文说明“让每一笔，都有去处”。视觉方向为干净的个人财务工作台：温灰画布、清晰表格、少量主题色（默认青绿）主操作、数值使用等宽数字。浅色与深色是两套完整令牌；显示模式默认“跟随系统”，可手动固定为浅色或深色；主题色可从预设选择或自定义。规则见 §2.2。

| --- | --- | --- | --- | --- |
| canvas | #F5F6F8 | #11181B | 页面背景 | 否 |
| surface | #FFFFFF | #1A2428 | 卡片、表单、弹层 | 否 |
| text | #182D32 | #ECF4F3 | 正文 / 金额 | 否 |
| muted | #52666D | #A4B6BA | 次级信息，需对比度验证 | 否 |
| border | #DFE7E8 | #34474D | 表格、输入边界 | 否 |
| primary | 默认 #07766A | 默认 #52CFB7 | 主要操作、链接、选中态、焦点环 | 是：预设或生成值，见 §2.2 |
| on-primary | #FFFFFF（自动选择） | #0F1F22（自动选择） | 主色按钮上的文字 | 是：取白 / 深色中对比度更高者 |

0.3 将默认 primary 浅色值由 #087F72 调为 #07766A：原值在 soft 底（标签、选中态）上仅约 4.2:1，未达到 AA。分类图表色 #087F72 是图形色，不受影响。

字体系统：本地系统字体，中文 Microsoft YaHei / PingFang SC；正文 14–16px，页标题 28px，KPI 32px，辅助文字不得低于 12px。移动输入至少 16px。数字 font-variant-numeric: tabular-nums。

空间使用 4/8/12/16/24/32/48px 阶梯。卡片圆角 16px、输入 10px、模态 20px；只在弹层使用明显阴影。按钮高度桌面 40px，触摸目标至少 44×44px。图标配可访问名称，不能只靠红绿区分。

图表使用固定语义色，不随主题色变化：收入 positive 绿、支出深蓝、预测虚线、比较期浅灰；最多 6 个类别，剩余合并“其他”。不做 3D 饼图、双轴混淆、装饰性面积缩放。折线显示币种和期间；分类优先水平条形图，可加圆环辅助。

### 2.1 ECharts 与动效规范

所有统计图表统一使用 Apache ECharts：总览在“支出走势”（低强度渐变面积 + 折线）与“收支对比”（分组柱形）间切换；分类排行为圆角水平条形；分析页用环图展示支出占比。分类色彩在排行和环图间保持一致，图例、悬浮值、期间和币种齐全；金额标签始终是实际值。

| 场景 | 动效 | 时长与限制 |
| --- | --- | --- |
| 首次进入总览 | 卡片轻移入场，柱形依序增长，折线绘制 | 卡片 340–420ms，位移 ≤10px；图表 550–750ms；错峰 ≤180ms |
| 分析页支出构成 | 环形扇区展开，悬浮轻微强调 | 展开 850ms，悬浮扩张 ≤5px；不循环旋转 |
| 切换币种 / 趋势模式 / 数据更新 | 同一图表实例 setOption 平滑过渡 | 更新 420ms，cubicInOut；保留焦点与已有内容 |
| 深浅模式 / 主题色切换 | 一次性重绘；切换瞬间临时禁用 CSS 过渡，图表同实例 setOption 换色 | 不重播入场动画，不 dispose 重建；减少动态效果时同样即时 |
| 按钮 / 弹层 | 轻微按压、背景变化；弹层淡入并上移 | 按钮 160ms，弹层 220ms；不影响立即操作 |
| 预算进度 | 从左侧展现到实际占比 | 650ms；百分比数字直接显示真实值 |
| 容器尺寸变化 | resize 重排 | 不重新播放入场动画，不重建页面 |
| 减少动态效果 | ECharts animation=false；关闭 CSS 过渡与关键帧 | 即时呈现，同样可操作；动态切换系统偏好也生效 |

不得加入跑马灯、无休止脉冲、数字随机滚动、弹性金额过冲等装饰。折线平滑须保持时间顺序并避免负数过冲，不插入虚构交易。图表保持在 366 点以内；低端设备必要时关闭动画而保留真实数据。

桌面使用 hover / click；移动支持 tap 提示与钻取。图表下方提供可展开的数据表 / 分类按钮，键盘和屏幕阅读器无需依赖 SVG 元素本身即可访问。原型本地包含图表脚本，断网仍可评审。

### 2.2 外观：深浅模式与主题色

外观只改变显示方式，不改变任何账务数据、金额口径或审计记录。

**显示模式**

| 选项 | 行为 |
| --- | --- |
| 跟随系统（默认） | 按操作系统 prefers-color-scheme 使用浅色或深色；系统切换外观时页面与图表即时更新，无需刷新 |
| 浅色 / 深色 | 手动固定，不随系统变化；设置处同时提示“系统当前为浅色 / 深色” |

解析顺序：用户手动选择 > 系统偏好 > 浅色（无法检测时）。没有已保存偏好时按“跟随系统”。

**主题色预设**：并排显示浅色 / 深色两个值，预设已逐一校验；表中为该模式下最低对比度（主题色文字、按钮文字、soft 底上的次级文字三项取最小）。

| 预设 | 浅色 · 最低对比度 | 深色 · 最低对比度 |
| --- | --- | --- |
| 青绿（默认） | #07766A · 4.73:1 | #52CFB7 · 5.47:1 |
| 海蓝 | #1F6FB2 · 4.54:1 | #7DB8F0 · 5.58:1 |
| 靛蓝 | #4C5BD4 · 4.80:1 | #A5AEF8 · 5.55:1 |
| 紫罗兰 | #7B4FC0 · 4.85:1 | #C5A8F4 · 5.54:1 |
| 玫红 | #B02E7C · 5.03:1 | #F29BCF · 5.59:1 |
| 松绿 | #2B7535 · 4.89:1 | #84D492 · 5.41:1 |
| 石墨 | #4B5D67 · 5.14:1 | #B3C4CC · 5.38:1 |

预设刻意不含红、橙、琥珀色相，避免与错误、支出、警告语义混淆。

**自定义主题色**

1. 输入：取色器或十六进制文本（#RRGGBB，也接受 #RGB 并展开）。输入中只应用完整的 6 位值；提交时非法值内联报错，保持当前主题不变。
2. 生成：在 OKLCH 色彩空间保持色相。浅色模式下，所选颜色已满足要求则原样使用，否则逐步降低明度；深色模式下明度至少 0.72，并逐步提高直到满足要求。需要时降低彩度以留在 sRGB 色域。要求为：主题色作为文字在 surface、canvas、soft 上 ≥4.5:1；按钮文字（白色或 #0F1F22，自动取对比度高者）≥4.5:1；soft 底上的 muted 文字 ≥4.5:1。
3. 展示：设置处并排预览浅 / 深两种结果、实际色值和最低对比度；颜色被调整时用一句话说明原因（例如“浅色模式已自动加深，满足 WCAG AA”）。
4. 提示：与错误色或警告色的 OKLCH 色相差分别小于 30° / 20°，且彩度 ≥0.06 时，显示非阻断提示“接近错误 / 警告色，建议换一个”，用户仍可使用。
5. 存储：保存用户原始输入和生成算法版本 palette_version，不信任客户端提交的生成结果；算法升级时重新生成，旧色值不能绕过对比度要求。

**作用范围**

- 跟随主题色：主按钮、链接、选中导航、焦点环、分段控件与开关的选中态、标签 / 提示条 / 首个 KPI 卡的 soft 底、正常状态进度条、侧栏色调、品牌标记。
- 不跟随主题色：收入 / 支出 / 警告 / 错误等语义色，图表数据色（收入、支出、分类），金额正负号。危险操作按钮始终使用 negative 色加明确文字；预算超过 80% 时除变色外显示“⚠ 接近上限”，因此主题色与警告色接近时信息也不丢失。

**入口与交互**

- 顶栏“外观”按钮：桌面为锚定右上的浮层，背景不加遮罩模糊，便于实时观察整页效果；移动端为底部 sheet，适配 safe-area。移动“更多”页也有“外观”入口。P13 设置页复用同一组件。
- 结构：显示模式三段单选（浅色 / 深色 / 跟随系统，图标加文字）→ 主题色单选（7 个预设 + 自定义；色块以对角线同时显示浅 / 深色值，选中项用 ✓ 和外圈标识，不只靠颜色）→ 自定义输入 → 浅 / 深预览 → “恢复默认”（跟随系统 + 青绿）与“完成”。
- 即时生效，无单独保存按钮。打开时焦点在当前模式；方向键在单选组内切换并即时预览；Esc 或“完成”关闭，焦点回到打开入口。

**持久化与首帧**

- 登录用户偏好随账号保存并跨设备同步（PATCH /api/v1/me/preferences），同时写入非敏感 Cookie，供 SSR 首帧和登录页等未登录页面使用。保存失败时保留本设备设置，并提示“未同步到账号，仅本设备生效”。
- 首帧不得闪烁：SSR 在 html 元素上输出 data-theme（仅手动模式）和主题色 CSS 变量；“跟随系统”完全由 CSS 媒体查询处理，不依赖客户端脚本。
- 同步 color-scheme，使原生下拉、日期控件、滚动条随模式变化；按模式输出 theme-color meta，移动浏览器地址栏随之变色。
- 系统启用强制颜色（forced-colors: active，如 Windows 高对比度）时不覆盖系统颜色；主题色设置不生效，但界面仍完整可用。
- 原型使用 localStorage 模拟持久化，并在 head 中同步执行 theme.js 以避免闪烁。

**验收**

- 3 种模式 × 系统浅 / 深共 6 种组合解析正确；“跟随系统”下切换系统外观后，页面和图表即时更新，图表实例不重建。
- 全部预设 × 2 种模式，以及白、黑、纯黄、纯红、纯绿、纯蓝等极端自定义色，实际渲染的关键颜色对比度均 ≥4.5:1：主题色文字、按钮文字、soft 底次级文字、侧栏文字与焦点环。
- 刷新或重新登录后保持选择，首帧主题正确；语义色和图表数据色不随主题色变化。
- 外观浮层 / sheet 在 360px–1920px 下无溢出，键盘与读屏可完成全部操作。

| P13 /settings/appearance | 显示模式（浅色 / 深色 / 跟随系统）、主题色预设与自定义、浅 / 深预览、恢复默认；与顶栏外观浮层共用组件 | 个人偏好而非账本设置，viewer 也可修改；即时生效并同步账号；自定义色自动满足 AA；见 §2.2 |

### 4.1 P03 记账字段和操作

| 字段 | 默认 / 必填 | 校验与反馈 |
| --- | --- | --- |
| 类型 | 支出；必填 | 转账显示源 / 目标账户双金额，不显示收支分类 |
| 结算金额 | 空；必填 | 十进制键盘；按账户币种精度；0、负数、超范围内联报错 |
| 账户 | 最近使用；必填 | 必须属于当前账本且未归档；不得用隐式创建账户解决缺失 |
| 分类 | 最近分类建议；收支必填 | 用户选择优先；可选“未分类”，不让 AI 自行确定高置信未知类别 |
| 发生时间 | 账本时区当前时间；必填 | 展示时区；未来时间可保存计划，不自动算已发生 |
| 商家 / 备注 | 可选 | 长度限制；纯文本处理，外来内容视为数据 |
| 原币金额 / 币种 | 默认同结算；可选展开 | 外币时同时显示结算金额与参考率；真实扣款覆盖估算 |
| 汇率口径 | 自动快照 | stale / missing 必须明确选择，不能自动提交不完整折算 |
| 关联订阅 | 可选 | 从账单入口进入自动关联 occurrence，避免重复付账 |

桌面按 N 在无输入焦点时打开，Esc 关闭；存在未提交更改时提示保留 / 放弃。移动全屏 sheet 顶栏保存，金额优先聚焦；应允许一只手完成常用表单。

提交成功：返回上一页并保留筛选；toast 显示交易金额、币种，可查看详情；不得用“撤销”来删除原始审计记录。失败保留输入，滚动到首个错误；网络超时保留相同幂等键并查询提交结果。

退款入口显示可退余额、原币与到账账户；默认关联原分类。更正金额在确认页对比“原值 → 新值”和余额影响。作废必须显示具体交易与影响，不使用含糊的“确定吗”。

### 4.2 订阅卡片与日历

卡片内容顺序：服务名称 → 原币金额 / 周期 → 下次扣款日期与天数 → 账户 / 分类 → 提醒通道 → 更多。预测月均作为次级值并注明估算；不要同时用同等强调级别显示四个金额。

新增订阅分“基本资料、周期、支付账户、提醒”四组，同一页面完成；日期附近显示未来三次日期，修正 31 日、闰年错误。暂停要求恢复日期可选；取消保留已付记录并让用户选择“服务立即结束 / 本周期结束”。

### 4.3 提醒通道设置

每张卡片有通道名、用途、状态、最近测试、配置、测试按钮。个人微信与企业微信分别命名，不能合并为单一“微信”。

绑定流程：选通道 → 填写必要凭据 / 完成供应商绑定 → 预览脱敏测试消息 → 点击发送测试 → 返回平台受理结果 → 用户检查实际接收 → 启用规则。界面区分测试与真实账单。凭据保存后仅显示尾部掩码。

失败面板包括失败阶段、可读原因、最近尝试、下次重试；允许重新测试，不回显完整 Webhook 或 token。个人微信默认关闭金额 / 备注内容；在设置中明确选择才添加。

### 4.4 分析与钻取

支出 KPI = 期间有效支出 − 期间有效退款；收入单独计算；结余 = 收入 − 净支出。跨月退款按退款发生期抵减，原交易仍可追溯。期间内存在缺失折算时显示“已汇总 N 笔，M 笔待补汇率”。

趋势点击某日 → P02 带 dateFrom/dateTo；分类点击 → 保留日期、币种和 category；最近交易点击 → 详情 drawer。所有图表有“查看数据表”替代，键盘可以访问每个过滤入口。

订阅支出（P01 / P05）：每月 / 每年订阅 = 使用中订阅金额 × 每年周期数（÷ 12），按当前参考汇率（无则账本手工汇率）逐个折算后相加；停用节省 = 已暂停 / 取消的订阅若仍在扣款的同口径金额。每月订阅账单按扣款日归月：已支付为实色，待支付（未确认，以及超出生成窗口、按周期推算的预计账单）为同色斜纹，已跳过 / 已取消的账单不计；虚线为月均订阅。缺汇率的订阅不计入并注明数量。订阅统计是预测，与按历史入账的实际支出分开展示。

## 5. 共通交互状态

| 状态 | 呈现 | 下一步 |
| --- | --- | --- |
| 首次无数据 | 简短说明 + 新建账户 / 记第一笔；不显示误导零增长 | 完成首次操作 |
| 查询无结果 | 保留筛选，显示“当前条件下没有账目” | 清空或调整筛选 |
| 加载 | 保持布局尺寸 skeleton；局部刷新只更新对应区域 | 主导航可继续使用 |
| 接口错误 | 局部错误和 request_id，不清空已读内容 | 重试、反馈 |
| 无权限 | 解释当前角色限制 | 返回只读视图或联系账本 owner |
| 汇率延迟 | 来源 / 源时间 / 旧数据标签 | 使用旧率、手填、稍后补录 |
| 网络离线 | 只读提示；未提交输入留在当前内存 | 重连后核查状态再提交 |
| 版本冲突 | 当前服务器值与本地输入并排 | 重新载入或重新预览；不自动覆盖 |
| 部分通知失败 | 各通道分开显示 | 重试失败渠道，不重发全部 |
| 保存成功 | 简洁 toast + 详情入口 | 连续记账可保留分类账户、清空金额 |

V1 不在 localStorage 持久化账单备注或凭据；外观偏好可在本设备保存（原型用 localStorage；正式环境为非敏感 Cookie + 账号偏好），真实应用敏感草稿持久化需另外设计。

## 6. 无障碍与视觉验收

键盘可完成导航、筛选、记账与关闭弹层；dialog 有标题、焦点管理、Escape 和关闭后焦点恢复。输入都有可见 label；错误通过 aria-describedby 关联；状态变化以适当 live region 通知。动效按 §2.1 分层设定，尊重 prefers-reduced-motion。

正文目标 WCAG AA 4.5:1；大字 / 控件边界按相应标准验证。每个主题色在浅色、深色模式下都必须满足，自定义色由 §2.2 生成规则保证，不允许用户保存低对比度结果。图表有数值表和非颜色标记。金额不能用字号缩小解决窄屏溢出，应换行或缩短非关键标签。
